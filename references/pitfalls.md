# 踩坑清单

按"踩一次要花多久才能定位"排序。前三条是决定性的,务必先读。

---

## 1. 数值判色优先于视觉判读(最高优先级)

**现象**:反复被告知"天空灰蒙蒙""雪面发青绿""云不真实",按描述改完反而更糟。

**教训**:视觉模型在细微色偏上误判率很高。它分不清"蓝天的低饱和"和"阴天的灰",
也经常把查看器的背景色当成图的一部分。

**做法**:改完立刻用 `scripts/measure.py` 量渲染帧,不要靠肉眼。判据:

| 指标 | 位置 | 健康区间 | 越界含义 |
|---|---|---|---|
| 天空饱和度 | 上 35% | 0.30~0.45 | <0.25 发灰;通常是有巨型云挡镜头 |
| 天空亮度 | 上 35% | 0.50~0.65 | >0.75 过曝;通常是加性辉光过大 |
| 云像素占比 | 上 35% | 10%~30% | <3% 云被抹没了 |
| 地形亮部 RGB | 下 35% | 三通道差 <0.05 | 差值大 = 有色偏 |

**决定性的一次**:视觉模型连说几轮"天空灰蒙蒙"。量出来天空区饱和度仅 **0.089**、亮度
0.754,而 `sky.png` 贴图本身天顶饱和度是 0.506 —— **贴图没错,是场景在洗白它**。
再打粗网格(measure.py --grid)看到"画面顶部最白 0.75、往下反而变蓝 0.52",
与真实天空梯度相反,才锁定真凶是巨型积云挡镜头。改完后饱和度 0.089→0.422。

**推论**:先量被测对象本身(贴图)再量合成结果,两者对比能立刻区分
"素材问题"和"场景问题"。这一步省下的时间最多。

## 2. 云的真实尺度:精灵做太大是"天空糊白"的头号原因

**现象**:天空整片发白、上下梯度颠倒、远景像被一层雾蒙住。

**根因**:把公告板云做成 `0.24~0.54 × size` = **5.8~13 km 宽**(真实积云才 1~3 km),
且扎在距峰顶 2.4~8.6 km 处,**正好落在相机环绕半径(7~12.6 km)里** ——
相机直接怼在巨型白云前面。

**正确尺度**:
- 云宽 `size * (0.05~0.19)`,即 1.2~4.6 km
- 环带半径 `size * (0.35~1.1)`,必须在相机轨道(`0.58~1.05 × R`)之外
- 高度分散 `±1200 m`,约 35% 再抬 `+2200 m` 做垂直发展,否则会投影成一条线

## 3. 值噪声最低频八度过疏 = 方块云

**现象**:云贴图出现大方块格子、条带、"纸状"重复纹理。

**根因**:`fbm_seamless(base=5)` 在 1024 分辨率上只有 5 个噪声单元,阈值后就是大方块。
域扭曲(warp)只能打断,不能根除。

**解法(三件事一起做)**:
1. 抬高基础频率:云海 base=6、积云 base=9、天空 base=11(原 5 全太低)
2. 加域扭曲打断格点
3. 模糊 —— **必须用 PIL 的 `ImageFilter.GaussianBlur`(C 实现,快)**。
   numpy 的 box_blur 在大半径下会算到崩(r=22 在 2048² 上是 7e11 次运算)

**模糊的副作用**:模糊会把分布压向均值,阈值必须跟着降,否则云被抹没。
实测 `blur(12,4) + 阈值 (cf-0.55)/0.45` 把天空云覆盖率抹到 **0.4%**(云没了);
改成 `blur(8,3) + (cf-0.50)/0.30` 回到 14%。**每次调模糊都要复测覆盖率。**

## 4. 等距天空贴图上不要做 band 限制

等距柱状(equirectangular)贴图里,地平线在图像**正中**(v=0.5)。
相机近水平俯视时可见天空只占地平线以上很窄一条(约 17°),
**任何"云只铺在某段"的 band 限制都可能误伤可见区**,表现是天空看起来无云。

**最稳做法**:让云均匀铺满整张穹顶贴图,落在地平线下的部分本来就看不见。

---

## 5. 精灵远近一样清晰 = 读成"贴上去的贴纸"

所有云无论远近都同样清晰、同样亮,是"贴纸感"的直接来源。
真实大气里远处的云会失去对比并融入天色。

**解法**:按相机距离做空气透视 ——
`f = smoothstep(dist, size*0.7, size*2.6)`,
`opacity *= (1 - 0.62*f)`,色调同时趋向天色。廉价且效果明显。

---

## 6. 平面云 vs 公告板云(方案选择)

- **平面云**(`PlaneGeometry` 铺云海):在高位俯瞰相机下会被前景山脊挡掉只露一条带,
  掠射角还会拉伸成方块条带,**怎么调径向淡出都根治不了**。
- **公告板云**(`Sprite` + 柔和 puff 贴图):离散云朵、有体积、不拉伸。

但注意:低位**云海**仍然用平面(它在相机下方,掠射问题不严重),
只有**环绕峰顶的积云**必须用公告板。两者用途不同,别一刀切。

## 7. GLSL 变量名撞车

新增 `float c` 撞上已有的 `vec3 c`(颜色)→ `'c' : redefinition`,
three.js 会在控制台贴出 `VALIDATE_STATUS false` 加行号和上下文,很好定位。
**在已有 shader 里加变量前先搜一遍短名(a/b/c/f/t/n)是否已被占用。**

另一个高频错误:在 GLSL 里引用 JS 侧变量(如 `size`),着色器里根本不存在,
必须显式声明为 uniform。

## 9. 性能判断的边界

**无头浏览器能验证"画面对不对",不能验证"跑得快不快"**。
软件光栅(SwiftShader)下 3D 场景只有 1~3 fps,**测出的 fps 一律不可用**;
但截图、控制台报错、构图、色彩都可信。要报性能必须回真机 / GPU。

另外:卡住时**先做分阶段计时**,别凭直觉优化。实测中"画面渲染"只占 27s,
`browser.close()` 却卡了 30s,占全片耗时 90% —— 直觉完全指向错的地方。

## 10. 高差小的地形(高原面):AO 不是可选项

卡瓦格博高差 4632m,靠"山挡山"的投射阴影就有层次。换成唐古拉山(各拉丹冬)后,
12km 范围内高差只有 **1346m**、投射阴影覆盖 **2.9%**,画面 78% 的像素挤在亮度 0.5~0.85 ——
读起来就是"发光的白石膏"。

**判据**:渲染一帧,统计亮度直方图。若 `lum<0.35` 的暗部 < 5%、且 0.5~0.85 占 70% 以上,
就是立体感不足,不是调色能解决的。

**解法**:`build_world.py` 现在会自动烘 `ao.png`(双尺度曲率,重映射到 0.48~1.0)。
关键接线有两条,缺一条都几乎无效:

```glsl
vec3 amb = ... * mix(0.55, 1.0, ao);       // 只影响环境光:实测 std 纹丝不动
float alb = gAlbedo * ... * mix(0.74, 1.0, ao);  // 还要调制反照率:褶皱本就积不住雪
```

只做第一条时实测 `std 0.128 → 0.128`(完全没变),两条都做才 `→ 0.131` 且暗部明显增加。

## 11. PIL GaussianBlur 不处理环绕 → 天空球上一道竖直硬缝

`ImageFilter.GaussianBlur` 把图像外当作无关像素,所以贴图**左右边缘对不上**。
贴到 `SphereGeometry` 上就是一道从上到下的竖直接缝 —— 云越多越明显。

**判据**(不用看图):`abs(sky[:,0] - sky[:,-1]).mean()`。实测修前 **0.0723**、最大行差 **0.413**;
修后 **0.0011 / 0.0078**。

**解法**:横向平铺三份再模糊,裁中间:
```python
def _blur_wrap(arr, radius):
    h, w = arr.shape
    return _blur(np.tile(arr, (1, 3)), radius)[:, w:2*w]
```
垂直方向不需要(极点不收拢)。

## 12. 无头浏览器会缓存贴图,"改了参数画面却纹丝不动"

最浪费时间的一个坑:重烘了 `sky.png`,连续三轮改参数,渲染帧的天空数值**逐位相同**
(0.777/0.210 反复出现),一度以为是判据或着色器坏了。

**解法**:在 `render.js` 里
```js
await page.setCacheEnabled(false);
await page.goto(`...${PAGE}?t=${Date.now()}`, ...);
```
两条都加。**判据**:改完贴图后先确认 `curl` 拿到的字节数与磁盘一致,再怀疑渲染。

配套:改含中文的 HTML/JS 后,别用 Bash 的 `grep` 确认改动是否落盘(本机对含中文文件常给假空),
用 Grep 工具查。

## 13. 判据必须排除云像素,否则多云天空必然误报

"上 35% 的平均饱和度/亮度"在云多时一定偏灰偏亮。实测 36.7% 云量时 sat 0.210、lum 0.777,
按旧判据报"发灰+过曝",但把云像素剔除后是 **sat 0.288、lum 0.703(健康)** ——
差点为了一个不存在的问题继续调参。

`measure.py` 已改为先算云掩码、再在**非云像素**上统计天空底色。看 `sat_clear / lum_clear`。

## 14. 换位置时先看高差和阴影占比,再决定 km

`build_world.py` 输出里的这两行要在动手调色前读一遍:

```
[shadow] 平均受照 0.94  全影占比 2.9%
[ok] 高程 5235-6581m
```

- **高差 / 范围** 决定山看起来陡不陡。26km 配 1532m 高差 = 5.9% 坡度,平得像丘陵;
  缩到 12km 后同样高差坡度翻倍,立刻有形。唐古拉山这种高原面,km 给大了就是一片雪原。
- **纹理被 mipmap 吃掉**:4096 贴图盖 26km = 6.3m/px,山体在画面里占 700px 横跨 26km 时
  每像素 37m,要降 6 级 mipmap,雪的细节(实测局部 std 仅 0.039,只有其他区域的 1/3)全被抹平。
  缩范围是唯一解,不是换更大贴图。

## 15. 云海平面这个方案本身是错的,别救它

水平面 + 俯视相机 = 一层半透明白膜盖在山体上。实测画面 y≈0.56 处有横跨 70% 宽度、
梯度 0.034 的水平硬边,而且云会"穿过"山体。做成三层错高只是让它更厚,不改变"贴膜"的本质。

用户的原话是"流动的云在山体间穿,已经穿模了"。**平面方案的几何前提就是错的**:
相机高于云面时,云面必然覆盖它后面的地形。

正确做法:云只由 sprite 承担,并且全部放在相机轨道之外。

## 16. 卫星瓦片色调不连续 = "不自然的方形色块"

ESRI 相邻瓦片常来自**不同时间/不同卫星**,同一区域叠出来的调子不同。硬拼
(`mos[oy:oy+256, ox:ox+256] = im`)就是一块块肉眼可见的方块,而且**在渲染帧的
列/行均值差分里几乎测不出来**(实测只有 0.0015——因为接缝细,平均后被抹平),
只能直接看 `satellite.jpg` 才发现。

**解法**:逐瓦片向全局均值做增益校正(夹 0.82~1.22,避免把雪压灰、把岩提白)。
以瓦片均值的中位数为目标,避免个别极端块拉偏。唐古拉山实测 **618/625 块**都被校正了,
说明这个问题普遍存在,不是偶发。

## 17. 雪区没有纹理 = "水泥感",提亮只会变成死白

卫星影像的雪区是**接近纯白且几乎没有纹理**(实测 5×5 局部 std 仅 0.039,
是岩石区的 1/3)。所以:

- 压暗雪 → 变成灰水泥
- 提亮雪 → 变成一片死白

两者都不对。必须**程序化补一层高频**(`detail.png`,中性 0.5±0.09),只作用在雪区
(`snowM = smoothstep(0.62, 0.88, luma)`),提亮时才有层次。

三个配套要点:
1. 雪不能跟岩石一起被压暗:`alb *= mix(1.0, 1.34, snowM)`
2. 雪要偏冷蓝:`base = mix(base, base * vec3(0.93, 0.97, 1.07), snowM)`
3. **细节贴图的低频档权重不能大**,否则雪面被拉出方向性条纹,读成"水波/绸缎";
   三档频率取 15/44/120、权重 0.34/0.36/0.30,平铺次数也要小(×1.15,不能 ×3)

## 18. 积云贴图要"泡泡并集",不是"径向衰减 × 噪声"

旧的 `径向衰减 × fbm + 6px 模糊` 做出来是**近似正圆的扁平团块、边缘硬锯齿**,
贴到天上一眼是纸贴纸。

积云的辨识特征是"多个圆顶堆在一条平云底上":
- 用 **30 个小高斯泡泡取 `max`**(不是 `sum` —— sum 会把相邻泡泡平滑成一个光滑外壳)
- 云底压平:`field *= clip((0.70 - vpos) / 0.14, 0, 1)`
- 羽化 blur 6~9 就够,**blur 16 会退回成光滑土豆**
- 受光 = 0.40×厚度 + 0.60×垂直位置,再乘 fbm 做内部翻滚

数量上,一堆小云读作"纸巾屑",**6 个簇、每簇 2~3 朵、尺度幂律**才像天空。

## 19. 地面"方块"的最终解法是换影像源,不是调色

ESRI World Imagery 的相邻瓦片来自不同时间/不同卫星。实测瓦片周期 **174px**
(=256px 原瓦片,自相关 **0.370**),而且**块内纹理内容不同**(一处纯雪、一处露岩),
所以:

- 全局均值校正 → 反而更明显(0.370,块内雪岩比例不同,边界纹理断层更锐利)
- 邻域平滑均值 + 接缝 3px 柔化 → 0.238,仍看得出来
- 压平低频亮度 → 0.318,更差(块间色相差异被放大)
- 加 2.6px 模糊 → 只是把锐边磨软,块还在

**真正的解法:换 `--imagery-source s2`(Sentinel-2 年度无云合成,EOX 公开瓦片)。**
全球统一合成,不存在"瓦片来自不同时间",**方块彻底消失**。
代价是雪原上几乎是纯白、细节要由 normalMap + detail.png 提供 —— 对雪线以上地形反而更接近真实。
端点:`https://tiles.maps.eox.at/wmts/1.0.0/s2cloudless-2023_3857/default/g/{z}/{y}/{x}.jpg`

## 20. 天空贴图开 mipmap 会把云整个抹平

天空球半径 `size*9`,相机只看球面很小一块 → 采样落到很高的 mip 级别,
**贴图上有 36.8% 云,渲染出来一朵都没有**,而且这个现象在贴图上完全看不出来(贴图是好的)。

```js
skyTex.minFilter = THREE.LinearFilter;
skyTex.generateMipmaps = false;      // 天空球不需要 mipmap,它离相机恒定远
```

排查方法:**用彩色调试贴图实测 UV 范围**。给 sky.png 每 0.1 的 v 填一种纯色,渲一帧看画面顶部的颜色,
就能直接读出"可见天空落在 v 0.40~0.55"。比猜强得多 —— 之前我按 v=0.42 加权,结果那段根本没有云。

## 21. 天空云的可见带权重必须够强,否则等于没云

可见带只有 v∈[0.40,0.55]。往那里加权重时:

- 加 0.22 → cov≈0.22,混合出的天空饱和度 0.25,**既看不出来也过不了判据**
- 加 0.58 → 又连成白带、天空过曝(lum 0.83)
- **0.44 左右**才落在"有云但不糊"的区间

## 22. 云的死局:三个方案都不通,这是硬约束

- **天空贴图**:能做出薄云,但做不出"一朵朵有边界的云"(可见带太窄)
- **公告板精灵**:凑近一定是纸贴纸;唯一藏法是推到 1.1~1.9×size 之外 + opacity 0.42~0.68,退成背景云层
- **体积云(ray marching)**:需要 GPU。实测 `GPU=1`(ANGLE/Metal)只比软件光栅快 **2 倍**
  (0.17s vs 0.34s/帧),而体积云至少慢 20~50 倍 —— **跑不动**

要真正解决云,只能换渲染后端(Blender/Cycles、Unreal),headless Chrome 这条路到头了。

## 23. 雪面"灰方块印子"的元凶是 detail.png 的值噪声格点

用户报"雪面上那些灰灰的方块印子"。用排除法一层层关卡才定位到:

| 关掉什么 | 现象 |
|---|---|
| 法线贴图 | 菱形消失、但**方形成片出现**(说明菱形和方块是两个源) |
| AO | **方块没变** → 不是 AO |
| 阴影 | **方块没变** → 不是阴影 |
| **detail.png** | **方块消失** ✓ |

**根因**:`fbm_seamless(base=15)` 在 2048 贴图上每 136px 一个值噪声格点,近景放大后
每一格就是一个灰方块。之前为配合"雪纹"观感把 base 从 7 提到 15,仍然太粗。

**解法**:base 提到 34 / 95 / 260,并整图 `_blur(d, 2)` 抹掉格点。

**顺带修掉的两个**:
- 法线贴图强度 0.34 会把 DEM 的采样噪声放大成规则**菱形/星形**格子 → 收到 0.16
- AO 在 grid(768) 上算、存成 2048 只是上采样,近景每像素仍是一块(15~25m 方块)
  → 改为在原始 elev 重采样到 2048 上算,并用 `box_blur(passes=4)` 代替 2 次(方核→近似高斯)

**方法沉淀**:这类"网格/方块"问题靠数值判据(列行均值差分)基本测不出来,必须
**裁一块放大 2~3 倍用肉眼找规律**(规则 = 纹理/网格;随机 = 噪声),再用**逐层关卡做 A/B**。
一次只关一层,现象不变就换下一层 —— 比猜快得多。

## 24. 打光与空气透视:雪景真实感的四个杠杆(按性价比排序)

现状诊断(最后一帧的量化):

| 指标 | 数值 | 说明 |
|---|---|---|
| 远/近 std 比 | 0.47 → 0.55 | 空气透视的方向对,但幅度不足 |
| 动态范围 p95−p5 | 0.69 | 够,但中位数 0.72 偏高,画面偏"平白" |
| 投射阴影占比 | **2.9%** | 高差小 + 太阳角高 → 没有方向性光影 |

**1. 太阳高度角是最便宜的杠杆**
`--sun-alt 33 → 16`,阴影占比 **2.9% → 16.0%**,平均受照 0.94 → 0.78。
同一份地形,立刻从"阴天平光"变成"有受光面/背光面"。**改一个数字的事,先做这个。**

**2. 雪的镜面高光(低角度阳光下必加)**
雪是强反光材质(钻石尘/雪面反光)。只有漫反射的雪读作石膏:
```glsl
vec3 hv = normalize(sunDir + viewDir);
float spec = pow(max(dot(n, hv), 0.0), 42.0) * sh;
col += sunColor * spec * 0.85 * mix(0.20, 1.0, snowM);
```

**3. 太阳色温要与高度角匹配**
低角度阳光穿过更厚大气 → 偏暖。`sunColor` 从 (1.00,0.96,0.90) 收到 (1.00,0.88,0.72),
与蓝天环境光形成冷暖对比 —— 这一条对"真实感"的贡献常常被低估。

**4. 高度雾(不是距离雾)**
真实大气密度随高度**指数衰减**,所以山谷雾浓、峰顶清透。只按距离算雾,远近山的"空气量"是一样的,
山地最明显的层次感就没了:
```glsl
float altFac = exp(-max(vWorld.y, 0.0) / 850.0);   // 相对高度
f = clamp(f * mix(0.48, 1.35, altFac), 0.0, 1.0);
```

## 25. 缓坡上的"灰褐色印迹"是影像裸岩被放大糊出来的

S2 影像上 10m 分辨率的裸岩,放大到近景就是一片片灰褐色污迹。
**物理上缓坡积得住雪,裸岩只出现在陡坡** —— 用**几何法线**的 y 分量把缓坡上偏黄的部分擦回冷白:

```glsl
float flatness = smoothstep(0.32, 0.72, vN.y);            // 1 = 平缓(几何法线,不是 n)
float brownish = clamp((base.r - base.b) * 3.5, 0.0, 1.0); // 偏黄程度
base = mix(base, cleanSnow, flatness * brownish * 0.88);
```
⚠️ 必须用 `vN`(几何法线)而不是 `n`(混合后的法线),而且 `vN` 在 base 处理阶段就可用了;
用 `n` 会报 `'n' : undeclared identifier`(它定义在后面)。

## 26. 近景的"大块多边形"是网格密度不够

768 网格在 12km 上 = 15.6m/顶点,近景每个 quad 在画面上约占 150px,雪面上会显出大块斜边色块。
**加密到 1280**(7.8m/顶点)后基本消失,GPU 模式下帧时间仍是 0.14s —— 加密的代价几乎为零。

## 27. 真实感下一步还能做什么(按性价比)

1. **雪的次表面透光(SSS)**:背光面的雪透出蓝光,这是雪景最"灵魂"的一项,当前完全没有
2. **瑞利/米氏散射**:雾现在是单色混合;真实大气朝太阳方向偏暖、背向偏蓝
3. **阴影软化**:当前是硬阴影,真实山地有半影
4. **天空日轮**:画面里有光晕但看不到太阳本体
5. **雪面各向异性反光**:风吹雪的条纹有方向性
6. **云**(见第 22 节,方案性限制)
