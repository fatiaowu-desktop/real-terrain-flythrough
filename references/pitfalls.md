# 踩坑清单

按"踩一次要花多久才能定位"排序。前三条是决定性的,务必先读。

---

## 1. 数值判色优先于视觉判读(最高优先级)

**现象**:反复被告知"天空灰蒙蒙""雪面发青绿""云不真实",按描述改完反而更糟。

**教训**:视觉模型在细微色偏上误判率很高。它分不清"蓝天的低饱和"和"阴天的灰",
也经常把查看器的背景色当成图的一部分。

**做法**:改完立刻用 `scripts/measure.py` 量渲染帧,不要靠肉眼。判据:

| 指标 | 位置 | 健康区间 | 越界含义 |
|---|---|---|---|
| 天空饱和度 | 上 35% | 0.30~0.45 | <0.25 发灰;通常是有巨型云挡镜头 |
| 天空亮度 | 上 35% | 0.50~0.65 | >0.75 过曝;通常是加性辉光过大 |
| 云像素占比 | 上 35% | 10%~30% | <3% 云被抹没了 |
| 地形亮部 RGB | 下 35% | 三通道差 <0.05 | 差值大 = 有色偏 |

**决定性的一次**:视觉模型连说几轮"天空灰蒙蒙"。量出来天空区饱和度仅 **0.089**、亮度
0.754,而 `sky.png` 贴图本身天顶饱和度是 0.506 —— **贴图没错,是场景在洗白它**。
再打粗网格(measure.py --grid)看到"画面顶部最白 0.75、往下反而变蓝 0.52",
与真实天空梯度相反,才锁定真凶是巨型积云挡镜头。改完后饱和度 0.089→0.422。

**推论**:先量被测对象本身(贴图)再量合成结果,两者对比能立刻区分
"素材问题"和"场景问题"。这一步省下的时间最多。

## 2. 云的真实尺度:精灵做太大是"天空糊白"的头号原因

**现象**:天空整片发白、上下梯度颠倒、远景像被一层雾蒙住。

**根因**:把公告板云做成 `0.24~0.54 × size` = **5.8~13 km 宽**(真实积云才 1~3 km),
且扎在距峰顶 2.4~8.6 km 处,**正好落在相机环绕半径(7~12.6 km)里** ——
相机直接怼在巨型白云前面。

**正确尺度**:
- 云宽 `size * (0.05~0.19)`,即 1.2~4.6 km
- 环带半径 `size * (0.35~1.1)`,必须在相机轨道(`0.58~1.05 × R`)之外
- 高度分散 `±1200 m`,约 35% 再抬 `+2200 m` 做垂直发展,否则会投影成一条线

## 3. 值噪声最低频八度过疏 = 方块云

**现象**:云贴图出现大方块格子、条带、"纸状"重复纹理。

**根因**:`fbm_seamless(base=5)` 在 1024 分辨率上只有 5 个噪声单元,阈值后就是大方块。
域扭曲(warp)只能打断,不能根除。

**解法(三件事一起做)**:
1. 抬高基础频率:云海 base=6、积云 base=9、天空 base=11(原 5 全太低)
2. 加域扭曲打断格点
3. 模糊 —— **必须用 PIL 的 `ImageFilter.GaussianBlur`(C 实现,快)**。
   numpy 的 box_blur 在大半径下会算到崩(r=22 在 2048² 上是 7e11 次运算)

**模糊的副作用**:模糊会把分布压向均值,阈值必须跟着降,否则云被抹没。
实测 `blur(12,4) + 阈值 (cf-0.55)/0.45` 把天空云覆盖率抹到 **0.4%**(云没了);
改成 `blur(8,3) + (cf-0.50)/0.30` 回到 14%。**每次调模糊都要复测覆盖率。**

## 4. 等距天空贴图上不要做 band 限制

等距柱状(equirectangular)贴图里,地平线在图像**正中**(v=0.5)。
相机近水平俯视时可见天空只占地平线以上很窄一条(约 17°),
**任何"云只铺在某段"的 band 限制都可能误伤可见区**,表现是天空看起来无云。

**最稳做法**:让云均匀铺满整张穹顶贴图,落在地平线下的部分本来就看不见。

---

## 5. 精灵远近一样清晰 = 读成"贴上去的贴纸"

所有云无论远近都同样清晰、同样亮,是"贴纸感"的直接来源。
真实大气里远处的云会失去对比并融入天色。

**解法**:按相机距离做空气透视 ——
`f = smoothstep(dist, size*0.7, size*2.6)`,
`opacity *= (1 - 0.62*f)`,色调同时趋向天色。廉价且效果明显。

## 6. 平面云 vs 公告板云(方案选择)

- **平面云**(`PlaneGeometry` 铺云海):在高位俯瞰相机下会被前景山脊挡掉只露一条带,
  掠射角还会拉伸成方块条带,**怎么调径向淡出都根治不了**。
- **公告板云**(`Sprite` + 柔和 puff 贴图):离散云朵、有体积、不拉伸。

但注意:低位**云海**仍然用平面(它在相机下方,掠射问题不严重),
只有**环绕峰顶的积云**必须用公告板。两者用途不同,别一刀切。

## 7. GLSL 变量名撞车

新增 `float c` 撞上已有的 `vec3 c`(颜色)→ `'c' : redefinition`,
three.js 会在控制台贴出 `VALIDATE_STATUS false` 加行号和上下文,很好定位。
**在已有 shader 里加变量前先搜一遍短名(a/b/c/f/t/n)是否已被占用。**

另一个高频错误:在 GLSL 里引用 JS 侧变量(如 `size`),着色器里根本不存在,
必须显式声明为 uniform。

## 8. 环境/工程类

| 坑 | 症状 | 解法 |
|---|---|---|
| http.server 被回收 | 渲染时 `ERR_CONNECTION_REFUSED` | 用**正式后台任务**常驻,不要用 `cmd &`(命令结束即被回收) |
| puppeteer-core 找不到 | `Cannot find module` | 设 `NODE_PATH` 指向含它的 node_modules(常是 `~/.workbuddy/binaries/node/workspace/node_modules`) |
| 关浏览器巨慢 | 渲染只花 1 分钟,`browser.close()` 卡 30s | 帧落盘后 `Promise.race([browser.close(), timeout(1500)])`,不等它(render.js 已内置) |
| ffmpeg 被安全策略拦 | 组合命令里的 ffmpeg 报拒绝 | 把命令写进脚本文件再跑(encode.py) |
| PIL 中文渲染成方块 | `■■■` | 显式挂字体:`/System/Library/Fonts/Hiragino Sans GB.ttc`(本机无 PingFang.ttc);若字体路径也被拦,加 `--ascii-only` |
| 残留 Chrome 进程 | 后续基准测试全部失真 | 杀后台渲染任务后 `pkill -9 -f playwright_chromiumdev_profile`,测速前先清一遍 |
| 搬运的工具函数藏着只在某一分支触发的 bug | 主流程跑得好好的,换个参数就崩 | 对搬来的数值函数做一个 2 分钟自测:**常数场必须不变**、**delta 必须在每个轴都扩散**。实测 `box_blur` 的 `axis=1` 分支就是这样漏掉的 —— 因为 Python 条件表达式惰性求值,`axis=0` 时那条错误分支根本不会被执行到 |

## 9. 性能判断的边界

**无头浏览器能验证"画面对不对",不能验证"跑得快不快"**。
软件光栅(SwiftShader)下 3D 场景只有 1~3 fps,**测出的 fps 一律不可用**;
但截图、控制台报错、构图、色彩都可信。要报性能必须回真机 / GPU。

另外:卡住时**先做分阶段计时**,别凭直觉优化。实测中"画面渲染"只占 27s,
`browser.close()` 却卡了 30s,占全片耗时 90% —— 直觉完全指向错的地方。

## 10. 高差小的地形(高原面):AO 不是可选项

卡瓦格博高差 4632m,靠"山挡山"的投射阴影就有层次。换成唐古拉山(各拉丹冬)后,
12km 范围内高差只有 **1346m**、投射阴影覆盖 **2.9%**,画面 78% 的像素挤在亮度 0.5~0.85 ——
读起来就是"发光的白石膏"。

**判据**:渲染一帧,统计亮度直方图。若 `lum<0.35` 的暗部 < 5%、且 0.5~0.85 占 70% 以上,
就是立体感不足,不是调色能解决的。

**解法**:`build_world.py` 现在会自动烘 `ao.png`(双尺度曲率,重映射到 0.48~1.0)。
关键接线有两条,缺一条都几乎无效:

```glsl
vec3 amb = ... * mix(0.55, 1.0, ao);       // 只影响环境光:实测 std 纹丝不动
float alb = gAlbedo * ... * mix(0.74, 1.0, ao);  // 还要调制反照率:褶皱本就积不住雪
```

只做第一条时实测 `std 0.128 → 0.128`(完全没变),两条都做才 `→ 0.131` 且暗部明显增加。

## 11. PIL GaussianBlur 不处理环绕 → 天空球上一道竖直硬缝

`ImageFilter.GaussianBlur` 把图像外当作无关像素,所以贴图**左右边缘对不上**。
贴到 `SphereGeometry` 上就是一道从上到下的竖直接缝 —— 云越多越明显。

**判据**(不用看图):`abs(sky[:,0] - sky[:,-1]).mean()`。实测修前 **0.0723**、最大行差 **0.413**;
修后 **0.0011 / 0.0078**。

**解法**:横向平铺三份再模糊,裁中间:
```python
def _blur_wrap(arr, radius):
    h, w = arr.shape
    return _blur(np.tile(arr, (1, 3)), radius)[:, w:2*w]
```
垂直方向不需要(极点不收拢)。

## 12. 无头浏览器会缓存贴图,"改了参数画面却纹丝不动"

最浪费时间的一个坑:重烘了 `sky.png`,连续三轮改参数,渲染帧的天空数值**逐位相同**
(0.777/0.210 反复出现),一度以为是判据或着色器坏了。

**解法**:在 `render.js` 里
```js
await page.setCacheEnabled(false);
await page.goto(`...${PAGE}?t=${Date.now()}`, ...);
```
两条都加。**判据**:改完贴图后先确认 `curl` 拿到的字节数与磁盘一致,再怀疑渲染。

配套:改含中文的 HTML/JS 后,别用 Bash 的 `grep` 确认改动是否落盘(本机对含中文文件常给假空),
用 Grep 工具查。

## 13. 判据必须排除云像素,否则多云天空必然误报

"上 35% 的平均饱和度/亮度"在云多时一定偏灰偏亮。实测 36.7% 云量时 sat 0.210、lum 0.777,
按旧判据报"发灰+过曝",但把云像素剔除后是 **sat 0.288、lum 0.703(健康)** ——
差点为了一个不存在的问题继续调参。

`measure.py` 已改为先算云掩码、再在**非云像素**上统计天空底色。看 `sat_clear / lum_clear`。

## 14. 换位置时先看高差和阴影占比,再决定 km

`build_world.py` 输出里的这两行要在动手调色前读一遍:

```
[shadow] 平均受照 0.94  全影占比 2.9%
[ok] 高程 5235-6581m
```

- **高差 / 范围** 决定山看起来陡不陡。26km 配 1532m 高差 = 5.9% 坡度,平得像丘陵;
  缩到 12km 后同样高差坡度翻倍,立刻有形。唐古拉山这种高原面,km 给大了就是一片雪原。
- **纹理被 mipmap 吃掉**:4096 贴图盖 26km = 6.3m/px,山体在画面里占 700px 横跨 26km 时
  每像素 37m,要降 6 级 mipmap,雪的细节(实测局部 std 仅 0.039,只有其他区域的 1/3)全被抹平。
  缩范围是唯一解,不是换更大贴图。
